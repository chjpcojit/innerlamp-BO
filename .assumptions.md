# Assumptions

- **Login API** (contract from BE-Developer, innerlamp `docs/specs/api/openapi.yaml`): `POST {base}/v1/admin/auth/login` `{email,password}` → `{success,data:{access_token,admin,must_change_password}}`; errors `{success:false,error:{code}}`, branch on `error.code`. No refresh/logout endpoint; token TTL 30 min. Bearer only, CORS `*`. Base URL from `VITE_API_BASE_URL`, default `http://localhost:8081` (no staging URL yet). Code: `src/lib/auth/`.
- **Login layout** is a split screen: form on the left, decorative brand panel (gradient + grid, placeholder quote) on the right, hidden below `lg`. Omitted as there is no backend/route for them: social buttons, "forgot password", "sign up", "remember me". Logo is the placeholder `InnerShadowTop` icon; brand text and quote are placeholders; accent colors (amber/indigo) are arbitrary. Validate: confirm logo, colors and copy with product owner.
- **Root `/`** redirects to `/login`.
- **Change-password page** calls `POST /v1/admin/auth/change-password` (min 12 chars, enforced client-side too); on success stores the new token and goes to `/home`. On `UNAUTHORIZED` it clears the session and returns to `/login`.
- **Token storage**: `sessionStorage` (cleared on tab close; no logout endpoint, so no explicit logout yet). Validate: confirm with security/product.
- **Account lockout** error code not defined by BE yet (BE had not checked all usecases).
- **No route guard** on `/home` yet (only `/change-password` redirects to `/login` when there is no session).
